# ขอบเขตรหัสอ้างอิงระหว่างร้าน

| รายการ | ขอบเขต |
| --- | --- |
| รอบใหม่ | เลขลำดับตามวันบัญชีของร้านและต่อท้ายรหัสร้าน รหัสเดิมใช้ต่อได้ |
| บิลรับแทง ประวัติผู้รับจบ คิวแจ้งเตือนรอบ | ตรวจคู่ร้านและรอบทั้งที่ API และ foreign key |
| สมาชิก โต๊ะ สถานะร้าน สิทธิ์ และการเชื่อม LINE OA | คีย์แยกร้านอยู่แล้ว `member_no` เป็นเลขเก่าเพื่อจัดลำดับ เลขสมาชิกที่ใช้งานคือ `member_id` ต่อร้าน |
| รับ/จ่ายเงินโต๊ะ คำขอถอนซ้ำ | แยก retry key ตามร้าน และใช้ ID ของคำขอถอนที่บันทึกแล้วเป็น LINE retry key |
| ID ภายในและรหัสคำเชิญ | UUID หรือ ID ภายในยังไม่ซ้ำทั้งระบบ ใช้ตรวจสิทธิ์และกรองด้วยร้านในเส้นทางที่ให้ร้านเข้าถึง |
| บัญชีรับเงินร้านและสลิป | ผูกบัญชีรับเงินกับร้านเดียวและตรวจสลิปจริงซ้ำข้ามระบบ เพื่อป้องกันโอนครั้งเดียวแล้วได้เครดิตซ้ำ |
| แพ็กเกจ SaaS | ใช้บัญชีรับเงินกลาง ยอดคำสั่งซื้อและสิทธิ์แพ็กเกจแยกร้าน |

ลิงก์ชื่อร้านแบบ Open Graph มีให้ทั้งหน้าแอดมินและผู้เล่นสำหรับสามร้านปัจจุบัน ร้านใหม่และร้านที่เปลี่ยนชื่อจะต้องสร้างหรืออัปเดตหน้า Open Graph ต่อร้านก่อนพรีวิวใน LINE จะแสดงชื่อใหม่ ตัวหน้าแอดมินอ่านชื่อจากร้านโดยตรง

เผยแพร่ PR #51 แยกได้เพื่อแก้เปิดรอบก่อน การปรับคีย์ถอนใน PR นี้ให้ใช้ migration กับ Edge Function `shop-payments` ในช่วงเผยแพร่เดียวกัน หลังเผยแพร่ควรทดสอบถอนใน staging และตรวจว่าการกดซ้ำสร้างคำขอเดียวต่อร้าน ตรวจให้แน่ใจว่า PR #50 ไม่ย้อนการเปลี่ยนแปลงฟังก์ชันรับจ่ายเงินโต๊ะเมื่อนำมารวมภายหลัง
